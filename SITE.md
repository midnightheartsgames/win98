# Сайт pennygachi.men

С 17.11.2026 сайт живёт на виртуальном хостинге cloud4box (ISPmanager, пользователь user896926, сервер 185.154.20.52), а не на мини-ПК. Главная страница домена — визитка `web98-card/`: одно окно Win 98 без прокрутки с загрузками Win 98 и Star Rail 98 и ссылками на сайты о SR98. Прежние проекты в корне домена (ccc, mh-xray, mh-files и другие) на хостинг не переносились.

## Что где лежит

| На диске | На сайте |
| --- | --- |
| `web98-card/` | `/` |
| `web98-site/sr98/` | `/sr98/` (сайт игры, `play/` — игра в браузере, `StarRail98.apk`) |
| `web98-site/sr98wiki/` | `/sr98wiki/` (АстралВики 98) |
| `web98-site/kovcheg/` | `/kovcheg/` (Ковчег) |
| `npm run release -- win98 --full` | `/files/Win98.zip` и `/files/Win98-linux.tar.gz` |
| `npm run release` | `/update/` (для лаунчеров ещё и `/web98/update/`) |

`web98-card/.htaccess` отдаёт `/web98/update/...` из `/update/` без перенаправления (так ходят лаунчеры Win98.exe, StarRail98.exe и APK), остальные старые адреса `/web98/...` переводит на новые (`/web98/sr98/` → `/sr98/`, `/web98/Win98.zip` → `/files/Win98.zip`) и задаёт тип файлов `.apk`. Файлы в `/update/` заливает только `tools/release.cjs`, `site-deploy.py` их не трогает (как описано в разделе «Переезд на cloud4box» в `LAUNCHER.md`).

## Выкладка

Доступ только по FTP с TLS: shell у пользователя отключён. Логин и пароль лежат в `~/.netrc` (права 600) в строке `machine user896926.web-3.cloud4box.ru` и в git не попадают. Сертификат FTP самоподписанный, оба скрипта сверяют его отпечаток и не отправляют пароль, если он изменился.

```
python3 tools/site-deploy.py --dry-run
python3 tools/site-deploy.py
python3 tools/site-deploy.py --zip
```

Скрипт заливает только новые и изменённые файлы (размер и время изменения, время ставится через MFMT). `--zip` грузит архив под именем `files/Win98.zip.part` с докачкой и переименовывает его в конце. `--delete` убирает с хостинга файлы, которых больше нет на диске; папки `sr98`, `sr98wiki`, `kovcheg`, `files`, `update` и `web98` в корне он при этом не трогает. `--ls <папка>` показывает содержимое папки на хостинге.

## Домен

DNS домена в Cloudflare, запись `pennygachi.men` — A на 185.154.20.52 через прокси Cloudflare. На хостинге стоит самоподписанный сертификат ISPmanager, поэтому режим SSL в Cloudflare — Full. Для Full (strict) нужен сертификат Let's Encrypt в разделе «SSL-сертификаты» ISPmanager.

## VPS перед доменом

Из России сайт через прокси Cloudflare не открывается, а cloud4box напрямую не открывается из Украины. Поэтому перед доменом ставится VPS за пределами России: игроки из обеих стран ходят на него, он берёт сайт с cloud4box, а `/api/bugs` и `/api/net` отдаёт серверам на телефоне. Состояние на 19.11.2026: конфиг готов, VPS ещё не куплен, DNS не переключён.

| Файл | На VPS |
| --- | --- |
| `tools/vps/nginx/pennygachi.conf` | `/etc/nginx/conf.d/pennygachi.conf` |
| `tools/vps/nginx/pennygachi-origin.conf` | `/etc/nginx/snippets/pennygachi-origin.conf` |
| `tools/vps/setup.sh` | ставит nginx, certbot и ufw, получает сертификат, кладёт конфиги |

Что делает nginx:

- `/api/net` (WebSocket) и `/api/bugs` идут на `127.0.0.1:39900` и `127.0.0.1:39899` самого VPS, туда их пробрасывает обратный SSH-туннель с телефона (`ssh -R 127.0.0.1:39899:127.0.0.1:39899 -R 127.0.0.1:39900:127.0.0.1:39900`). Туннель нужен именно такой: приёмник верит заголовку `CF-Connecting-IP` только от 127.0.0.1, nginx всегда ставит в него адрес игрока, а net98 по этому заголовку закрывает `/api/net/admin/` (nginx ещё и отвечает на него 404). Пока туннеля нет, `/api/` отвечает 502, клиенты держат отчёты в очереди.
- Всё остальное идёт на cloud4box (185.154.20.52) с `Host: pennygachi.men`, сертификат хостинга не проверяется (он самоподписанный).
- Кэш на диске VPS (`/var/cache/nginx/pennygachi`, до 60 ГБ) кусками по 16 МБ, так что докачка `Range` работает с первого запроса. Блобы, манифесты и `.apk`/`.zip` с версией в имени в `/update/` хранятся 30 дней: их имена не переиспользуются. Остальное в `/update/`, `/files/` (Win98.zip) и `.apk` в `/sr98/` сверяется с cloud4box раз в минуту. Ответ несёт заголовок `X-Cache`.
- `http://<IP VPS>/vps-check` отвечает `pennygachi vps ok`: этим адресом игроки проверяют, что VPS у них открывается.

Порядок переезда:

1. Скопировать `tools/vps/` на VPS и запустить `sudo bash setup.sh`. Скрипт спросит токен Cloudflare (My Profile > API Tokens > шаблон «Edit zone DNS» для `pennygachi.men`). Сертификат Let's Encrypt берётся через DNS-запись, поэтому его можно получить до переключения домена; продление идёт само.
2. Проверить с ПК без смены DNS: `curl -I --resolve pennygachi.men:443:<IP> https://pennygachi.men/` и то же для `/web98/update/win98/stable.json`.
3. Попросить игроков из России и Украины открыть `http://<IP>/vps-check`.
4. В Cloudflare у записей `pennygachi.men` и `www` выключить прокси («серое облако») и указать IP VPS. Записи AAAA на старый адрес убрать. Откат: вернуть A на 185.154.20.52 и включить прокси.

Выкладка не меняется: `site-deploy.py` и `tools/release.cjs` заливают файлы по FTPS прямо на cloud4box, мимо домена. Новые файлы видны через VPS сразу, изменённые под старым именем — не позже чем через минуту.
