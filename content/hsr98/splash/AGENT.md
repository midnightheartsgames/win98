# Начальный промпт для агента, который делает сплеш-арты

Вставить в начало сессии целиком.

---

Ты делаешь пиксельные сплеш-арты героев для HSR 98 (Honkai: Star Rail 98), игры внутри проекта `I:\win98-clone`. Твоя работа: сгенерировать картинки по готовым промптам, проверить их, обработать скриптом и подключить. Код игры ты не пишешь и не меняешь, всё уже подключено.

## Что прочитать до начала

1. `content/hsr98/splash/PROMPTS.md` целиком: где арт показывается, формат 5:7 на сетке 200 × 280, зоны безопасности, общий стиль, блок «Если модель не слушается», промпты всех героев (44 арта героев HSR и 20 коллабораций).
2. `content/hsr98/splash/refs/INDEX.md`: ключи и файлы оригинальных Splash Art. Сами файлы лежат в `content/hsr98/splash/refs/<ключ>.png` (2048 × 2048, PNG с прозрачностью).
3. Для коллабораций оригиналов нет. Референс героев CCC: `content/CCC/*.png`. Для остальных (Мияби, Янаги, Фролова, Скар, герои KonoSuba и Persona 4, Билли, Николь, Энби) попроси пользователя приложить арт героя; пока его нет, эти герои идут в конец очереди.

Промпты не переписывай. Бери общий стиль и блок героя (`Hero`, `Pose`, `Scene`, `Palette`) из `PROMPTS.md` дословно. Правки допустимы только из блока «Если модель не слушается» и только когда без них результат не проходит проверку.

## Чем генерировать

Используй доступный инструмент генерации картинок, который принимает референсы (например fal через MCP или `um fal`, см. навык `fal-assets`). Если такого инструмента нет, остановись и скажи об этом: пользователь сгенерирует в ChatGPT, Gemini или Grok сам и положит файлы в папку, а ты возьмёшь только проверку и обработку.

Сырые генерации (2000 × 2800) храни вне репозитория: `C:\Users\MYPC\AppData\Local\Temp\opencode\splash-raw\<ключ>-<номер>.png`.

## Порядок работы

1. Пилот: `himeko`. Сделай 3–4 варианта, выбери лучший, обработай, покажи пользователю и дождись подтверждения стиля. Пока стиль не подтверждён, остальных героев не делай.
2. Утверждённый арт Химико прикладывай вторым референсом ко всем следующим запросам: палитра и толщина пикселей не должны гулять между героями.
3. Дальше пачками по 5 героев. Порядок: герои HSR по `PROMPTS.md` сверху вниз, затем Первопроходец в четырёх вариантах (по два на пол и путь), затем коллаборации.
4. На каждого героя: запрос = общий стиль + блок героя + референс (`refs/<ключ>.png`) + референс стиля. 3–4 варианта, один лучший.

## Проверка варианта (все пункты должны пройти)

- Картинка 5:7, клетки квадратные и одного размера, нет сглаживания, градиентов и свечения.
- Нет прозрачного, белого или пурпурного фона, нет формы-«кляксы» оригинала, рамки, текста, подписи.
- Один персонаж целиком, от головы до ступней. Макушка около 11% высоты, ступни около 89%. Голова, торс и ноги внутри центральной четверти ширины.
- Лицо читается: глаза, причёска, цвет волос и глаз, одежда и главный предмет совпадают с референсом. Герой не превратился в другого.
- Левая половина верхних 13% спокойная и тёмная. Края слева, справа, сверху и снизу темнеют, в них нет важных деталей.
- Герой самый яркий и контрастный элемент, сцена за ним темнее.
- Не больше 48–64 цветов.
- Для Первопроходца: мужской и женский арты различаются полом, сцена одна и та же.

Если вариант не проходит, перегенерируй с добавкой из блока «Если модель не слушается». Не выдавай слабый вариант за хороший.

## Обработка

```
python tools/hsr-cone-pix.py --splash <ключ> <путь/к/файлу.png> --pixel --colors 64 --preview <путь/к/preview.png>
```

Скрипт кладёт результат в `content/hsr98/splash/<ключ>.png` (200 × 280) и пересобирает `js/apps/hsr98/hsr-splash-pix.js`. Ключ равен ключу героя (`himeko`, `kafka`), у Первопроходца `trail-m`, `trail-f`, `trail_p-m`, `trail_p-f`. Если клеток в картинке меньше 200 × 280, генерируй заново крупнее, а не растягивай. Мелкая ошибка в цветах чинится ключами `--colors` и `--crop`.

Потом проверь результат тремя взглядами и посмотри на лист:

```
python -c "from PIL import Image, ImageEnhance as E; im = Image.open('content/hsr98/splash/himeko.png').convert('RGB'); card = im.crop((74, 0, 126, 280)).resize((56, 300), Image.NEAREST); asc = im.resize((276, 386), Image.NEAREST); dim = E.Brightness(asc).enhance(0.4); sheet = Image.new('RGB', (650, 386), (20, 20, 50)); sheet.paste(card, (10, 40)); sheet.paste(asc, (76, 0)); sheet.paste(dim, (362, 0)); sheet.save(r'C:\Users\MYPC\AppData\Local\Temp\opencode\splash-check.png')"
```

Слева карточка призыва (центральная полоса, лицо и силуэт должны читаться), в середине колонка возвышения, справа фон Следов при затемнении до 40%. Если на карточке героя не узнать, арт не годится.

## Правила

- Правь только файлы в `content/hsr98/splash/` (готовые арты) и журнал в `PROMPTS.md`. Скрипт и игровой код не трогай. Если нашёл ошибку в них, опиши её и остановись.
- `content/hsr98/splash/refs/` в git не попадает (`.gitignore`), оригиналы никуда не копируй и не публикуй.
- Не запускай `npm test`, циклы по `tests/*` и несколько тестов параллельно. После каждой пачки запускай только `node tests/hsr-splash.test.js`.
- Не коммить без прямой просьбы пользователя.
- Не рисуй откровенные позы и одежду. Арты показываются в общем интерфейсе.
- В коде и скриптах, которые ты вдруг напишешь, комментариев нет. В текстах игры пишем Microslop и Win, а не названия оригинальных компаний.
