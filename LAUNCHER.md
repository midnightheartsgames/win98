# Лаунчеры и обновления: Win 98, Star Rail 98 для ПК, кнопка в APK

План от 2026-10-28. Реализация идёт по этапам, один этап за шаг, после каждого этапа нужно одобрение. Решения автора и факты о мини-ПК записаны 28.10.2026, этапы 0–5 одобрены, этап 6 проверен на телефоне, этапы 7–9 сделаны: Win 98 1.3 и Star Rail 98 1.6.5 в stable. Остался необязательный этап 10 и полный Win98.zip с лаунчером для новых игроков.

Лаунчер для Android (Пароход 98) берёт отсюда подпись и сервер, но устроен отдельно: [ANDROID-LAUNCHER.md](ANDROID-LAUNCHER.md).

## Зачем

1. Win98.zip весит 1,7 ГБ. Сейчас любое исправление требует скачать архив заново и распаковать его. Лаунчер скачивает только изменённые файлы, обычно это единицы мегабайт.
2. Игрок узнаёт, что вышло нового, до обновления и после него, а не только на сайте.
3. Новости проекта видны там, где игрок запускает игру.
4. Star Rail 98 получает версию для ПК с обновлениями, а APK получает кнопку «Обновления» в главном меню.
5. Разработчик выпускает обновление одной командой. Ошибки из отчётов, исправленные в версии, сами попадают в список изменений.

## Цели, которые можно проверить

- Окно лаунчера показывает состояние меньше чем через 1 с после старта программы: список берётся из кэша, проверка идёт в фоне. Enter запускает игру.
- Проверка обновлений длится не больше 8 с. Если сервер не ответил, лаунчер переходит в состояние «Нет связи», а игра запускается как обычно.
- Обычное обновление Win 98 весит меньше 30 МБ и ставится меньше чем за минуту при 8 МБ/с.
- Сохранения не теряются никогда: обновление не трогает профиль, APK ставится поверх старого.
- Обрыв связи, закрытие окна или выключение ПК посреди обновления не ломают установку. Следующий запуск докачивает или доделывает.
- «Что нового» читается за 10 секунд: одна строка и до шести пунктов сверху, подробности по щелчку.

## Принципы

- Игра важнее обновления. «Запустить» и «Играть» работают всегда, кроме нескольких секунд, пока заменяются файлы. Обновление никогда не обязательное.
- Без всплывающих окон. Непрочитанное выделено жирным, в APK горит одна метка на пункте меню.
- У каждого лаунчера своя раскладка под его задачу: окно Win 98, страница сайта SR98, экран HSR в APK. Общий у них только движок обновления.
- Лаунчер ничего не сообщает об игроке. Он только скачивает файлы.

## Общая схема

```
ПК разработчика
  npm run release -- win98     сборка → версия → манифест → блобы → тексты → проверка запуска
                               → ssh/scp на мини-ПК (только новые блобы) → указатель версии последним
мини-ПК (статичные файлы)
  https://pennygachi.men/web98/update/
    win98/stable.json            какая версия последняя (с подписью)
    win98/manifest-1.15.json     все файлы версии: путь, размер, sha256
    win98/notes.json, news.json  что нового и новости
    sr98/...                     то же для SR98 на ПК, плюс APK
    blobs/3f/<sha256>.bin        содержимое файлов, один раз на любое число версий
игрок
  Win98.exe       → лаунчер Win 98 → «Обновить» → только нужные блобы → замена файлов → «Запустить»
  StarRail98.exe  → лаунчер SR98 (страница сайта) → то же → «Играть»
  APK             → Главное меню > Обновления → новый APK → установщик Android поверх старого
```

## Версии

| Продукт | Формат | Откуда берётся | Где видна |
| --- | --- | --- | --- |
| Win 98 | `1.N (ДДММГГГГ)`: первая сборка с лаунчером 1.0, каждый выпуск +1, в скобках дата сборки, например `1.0 (28102026)` (В1) | `release.cjs` берёт последнюю версию с сервера и прибавляет 1, дату ставит сам | лаунчер, «О программе Win», `report.json` |
| SR98 (ПК, APK, браузер) | `1.6.3`: два первых числа = `Hsr98.VERSION`, третье = номер сборки внутри этой версии; при смене `VERSION` снова 0 (В4) | так же | лаунчер SR98, строка в углу главного меню (`v1.6.3`), `VERSION_NAME` APK |
| HSR 98 внутри Win 98 | как сейчас, `VERSION` (1.6) | `hsr-core.js` | «CD-ROM v1.6» |

`versionCode` APK остаётся минутами с 01.01.2026: он и так растёт с каждой сборкой.

Обычная сборка без выпуска (`npm run build:exe`, `build:hsr98`) получает версию `dev`. Лаунчер с версией `dev` не обновляется.

Номер сборки Win 98 в скобках служит только для показа. Сравниваются версии по `1.N`: два выпуска в один день различаются номером, а дата у них одна. В `release.json` и указателе лежат отдельно `version` (`1.15`) и `build` (`02112026`). Везде, где видна версия Win 98 (лаунчер, «О программе Win», «Что нового», `--in` в отчётах), она пишется полностью: «1.15 (02112026)».

## Сервер обновлений

Только статичные файлы в `/srv/www/site/web98/update/` (`https://pennygachi.men/web98/update/`, папка создана 28.10.2026). Файлы отдаёт уже работающий static-site.

```
update/
  win98/
    stable.json, stable.json.sig      указатель канала stable
    test.json, test.json.sig          указатель канала test (В8)
    manifest-1.15.json(.sig)
    notes.json(.sig)                  все версии, новые сверху
    news.json(.sig)
    news/<id>.jpg                     картинки новостей
  sr98/
    stable.json(.sig), test.json(.sig)
    manifest-1.6.3.json(.sig)
    notes.json(.sig), news.json(.sig)
    StarRail98-1.6.3.apk
    StarRail98-PC-1.6.3.zip
  blobs/
    3f/3f2a...c9.bin                  содержимое файла, сжатое gzip, если так меньше
```

Имена файлов, которые не меняются после выкладки, содержат версию или хеш. Поэтому кэш Cloudflare никогда не отдаст старый файл: Cloudflare держит свою копию до вытеснения, а не только 4 часа. Файл под тем же именем не перезаписывается никогда.

Указатели `stable.json` и `test.json` Cloudflare не кэширует (JSON и `.sig` идут как DYNAMIC). К адресу указателя лаунчер добавляет `?t=<минута>`. К блобам параметр не добавляется: он ключ кэша Cloudflare, с ним каждый запрос шёл бы на мини-ПК.

Что учитывают клиенты (разведка мини-ПК 28.10.2026):

- Докачка: `Range` вместе с `If-Range: <ETag>`. Если файл на сервере другой, сервер отвечает 200 и всем файлом, клиент начинает блоб заново. В любом случае решает sha256.
- Ответ 404 приходит с HTML-телом. Клиент проверяет код ответа и `Content-Length`, а не только наличие тела.
- Block Exploits в NPM отвечает 403 на параметры с путями, адресами, `../` и `<script>`. Клиенты передают только полные пути к файлам, параметр есть только у указателя (`?t=`).
- User-Agent: обычный от `net.fetch` (Electron) и `HttpURLConnection` (Android). Cloudflare и NPM их пропускают, Bot Fight Mode выключен.
- Файлы больше 512 МБ Cloudflare Free не кэширует. Самый большой блоб 324 МБ, APK 35 МБ, архив SR98 около 150 МБ: всё кэшируется по расширению (`.bin`, `.apk`, `.zip`). `Win98.zip` (1,7 ГБ) идёт с мини-ПК, как и сейчас.

Блобы общие для всех продуктов. Одинаковые файлы Win 98 и SR98 (скрипты HSR) хранятся один раз.

### Указатель `stable.json`

```json
{
  "format": "win98-update",
  "v": 1,
  "product": "win98",
  "channel": "stable",
  "version": "1.15",
  "build": "02112026",
  "date": "2026-11-02",
  "commit": "9ab12cd",
  "manifest": "manifest-1.15.json",
  "blobs": "../blobs/",
  "runtime": "electron-44.4.5-win32-x64",
  "full": { "url": "../../Win98.zip", "version": "1.12", "bytes": 1838651654 }
}
```

Поле `blobs` говорит, откуда брать файлы. Если блобы когда-нибудь переедут на другой хостинг, меняется одна строка, а лаунчеры игроков менять не нужно.

У SR98 в указателе ещё два раздела: `apk` (`url`, `versionName`, `versionCode`, `bytes`, `sha256`) и `pc` (полный архив для новых игроков).

### Манифест

```json
{
  "format": "win98-manifest",
  "v": 1,
  "product": "win98",
  "version": "1.15",
  "runtime": "electron-44.4.5-win32-x64",
  "files": [
    ["resources/app/index.html", 94208, "3f2a...c9", 21503],
    ["resources/app/content/Fallout/MASTER.DAT", 339379746, "9c1e...07", 0],
    ["Win98.exe", 246032896, "a1b2...44", 0]
  ]
}
```

Поля строки: путь от папки программы, размер, sha256 исходного файла, размер сжатого блоба (0 = блоб не сжат). Файлы Electron (всё вне `resources/app`) тоже в списке: так лаунчер видит, что сменился сам Electron.

Сжатие gzip применяется, если файл меньше 64 МБ и сжатие экономит хотя бы 10 %. JS, CSS, HTML, JSON и MIDI сжимаются в 3–5 раз. JPG, MP3 и MP4 почти не сжимаются и идут как есть.

### Подпись

- Каждый JSON выпуска подписан ключом Ed25519, подпись лежит рядом в файле `.sig`. Закрытый ключ хранится только на ПК разработчика в `%USERPROFILE%\.win98-release.key`, как токен отчётов. В git его нет.
- Открытый ключ записан в `electron/updater.js`. Лаунчер не принимает указатель, манифест, тексты и новости без верной подписи.
- Блобы проверяются по sha256 из подписанного манифеста.
- Зачем: лаунчер заменяет `main.js` и `server.js`, а они работают с полными правами на ПК игрока. Без подписи взлом мини-ПК или аккаунта Cloudflare дал бы запуск чужого кода у всех игроков.
- APK подпись JSON не проверяет. Android сам не поставит APK с другим ключом и не поставит версию ниже установленной. Файл APK проверяется по sha256 только против битой загрузки.
- Потеря ключа = игроки не получат обновления, пока не скачают полный архив с новым ключом. Копия ключа хранится у автора отдельно, как копия `hsr98.keystore`.

## Ядро обновления `electron/updater.js`

Один модуль на Node для обеих программ, Win 98 и SR98 для ПК. Сеть передаётся параметром: в Electron это `net.fetch` (системный прокси, как у браузера), в тестах обычный `fetch`. Адрес сервера и папку установки можно подменить переменными `WIN98_UPDATE_URL` и `WIN98_UPDATE_ROOT` для тестов.

### Папки у игрока

```
Win98-win32-x64\                папка, куда игрок распаковал архив
  Win98.exe, *.dll, *.pak       Electron
  resources\app\                файлы системы и игр
    release.json                версия и манифест того, что сейчас установлено
  updates\                      создаёт лаунчер
    staging\<sha256>            скачанные файлы до установки, *.part = недокачанные
    backup\1.14\...             заменённые файлы прошлой версии для отката
    journal.json                план установки; существует, только пока она идёт
%APPDATA%\win98-clone\launcher.json   настройки, прочитанные записи, кэш текстов, время проверки
```

Настройки лаунчера лежат в файле, а не в localStorage. Поэтому сброс в «Архивации данных» их не сотрёт, и добавлять их в `backup-catalog.js` не нужно.

### Шаги

| Шаг | Что делает | Если прервать |
| --- | --- | --- |
| Проверка | `stable.json` и подпись, манифест и подпись, сравнение с `release.json`. Итог: последняя версия, есть обновление (число файлов и байты к загрузке), нужна полная версия (сменился Electron), нет связи. | ничего не меняется |
| Место и права | Свободно на диске (`fs.statfs`) не меньше загрузки, распакованного размера и 200 МБ запаса. Пробный файл в `updates\`. | — |
| Загрузка | 4 соединения. Каждый блоб пишется в `staging\<sha256>.part` с докачкой по Range, распаковывается и хешируется на лету, при совпадении sha256 переименовывается в `staging\<sha256>`. Три попытки на блоб с паузой 2, 5 и 15 с. Скорость за последние 3 с, оставшееся время. Пауза и отмена. | готовые блобы остаются, `.part` докачивается по Range |

Переименование повторяется при `EBUSY` и `EPERM`: файл может держать антивирус. | при следующем запуске найден журнал, установка доделывается из `staging\` |
| После | Более старый `backup\` удаляется, хранится одна прошлая версия. Лаунчер перезапускает программу (`app.relaunch`), чтобы точно работали новые `main.js` и `server.js`. | — |
| Откат | Файлы из `backup\` возвращаются на место, добавленные обновлением удаляются, возвращается старый `release.json`. | тот же журнал |
| Проверка файлов | sha256 всех файлов (1,9 ГБ за 10–20 с на SSD) против последнего манифеста с сервера. Повреждённые и пропавшие файлы качаются как обычное обновление. Без сети только список повреждённых. | ничего не меняется |

Особые случаи:

- Запуск из папки проекта (`npm run app`, `app.isPackaged === false`): обновления выключены, лаунчер пишет «Запуск из папки проекта: обновления выключены». Рабочую копию git лаунчер не трогает никогда.
- Папка только для чтения, например `C:\Program Files`: сообщение с путём и советом перенести папку. Права администратора не просим.
- Сменился Electron (поле `runtime` не совпадает): работающий exe заменить нельзя, лаунчер предлагает скачать полный архив. Сохранения при этом остаются (В5).
- Лаунчер никогда не ставит версию ниже установленной, кроме явного отката.
- `test.json` читается, только если в `launcher.json` записан канал `test`. Переключатель: пять щелчков по номеру версии в «Параметрах».

## Лаунчер Win 98

### Назначение

Окно появляется при каждом запуске `Win98.exe` (В2). Задачи по частоте:

1. Запустить Win 98. Это нужно почти всегда, поэтому это кнопка по умолчанию, Enter.
2. Поставить обновление, когда оно есть. Тогда кнопкой по умолчанию становится «Обновить».
3. Прочитать, что изменилось, и новости.
4. Редко: проверить файлы, откатить версию, изменить поведение при запуске.

Главное видно без щелчков: какая версия стоит, есть ли новая, сколько качать, что в ней.

Окно 600×440 без изменения размера. Рисуется стилями системы (`win98-base.css`, `window.css`) в окне Electron без рамки (`frame: false`). Заголовок перетаскивает окно, кнопки «Свернуть» и «Закрыть» взяты из системы. Углы окна прямые, это проверяется на Win 11.

- Порядок Tab: кнопка в «Состоянии», список, текст, «Параметры», «Запустить». Enter нажимает кнопку по умолчанию, Esc закрывает окно. Подчёркнутые буквы (`.win-accel`): Alt+З, Alt+О, Alt+П.

- Язык интерфейса RU или EN по `win98_language` системы. «Что нового» и новости только на русском (В9).

### Устройство

- `main.js`: сервер, затем окно лаунчера (`electron/launcher/index.html` с локального сервера), по «Запустить» окно системы. Окно системы создаётся до закрытия лаунчера, иначе сработает `window-all-closed`, и программа выйдет.
- `electron/launcher-preload.js` даёт странице `win98Launcher`: проверка, загрузка, пауза, установка, откат, проверка файлов, настройки, запуск. Обработчики в `main.js` отвечают только окну лаунчера (`event.sender`). Окно системы этих функций не видит.
- Если страница лаунчера не загрузилась за 10 с (испорчены её файлы), `main.js` показывает обычный диалог «Лаунчер не открылся. Проверить и восстановить файлы?» и проверяет файлы без страницы, прогресс виден на значке в панели задач.

## Star Rail 98 для ПК и его лаунчер

### Программа

- `tools/sr98-pc.cjs` (npm `build:sr98-pc`) собирает `dist/StarRail98-win32-x64/StarRail98.exe` тем же `@electron/packager` и архив `StarRail98-PC.zip` системным bsdtar, как Win98.zip.
- Внутри `resources/app/`: `main.js`, `preload.js`, `updater.js` (копия `electron/updater.js`), `launcher/`, `play/` (сборка `hsr98-standalone.cjs` с изданием `pc`). Исходники программы лежат в `tools/sr98-pc/`, как файлы standalone в `tools/hsr98-standalone/`.
- Игра открывается через `loadFile` (file://), как двойной щелчок по `index.html` сейчас. `files.js` уже работает на file://, новый код для этого не нужен. Сохранения лежат в `%APPDATA%\StarRail98`.
- Окно игры 1280×960, F11 включает полный экран, размер запоминается. Внешние ссылки открываются во внешнем браузере. Работает один экземпляр.
- Издание `pc`: `Hsr98Standalone = 'pc'`, строка издания «Издание «Ярило-VI» · ПК», канал отчётов `sr98-pc`. Сенсорная панель на ПК сама не появляется (`pointer: coarse`).
- Размер: Electron около 370 МБ после распаковки, архив около 150 МБ, из них игра около 35 МБ. Дальше обновления идут по файлам, как у Win 98.

### Назначение лаунчера SR98

Задачи те же, что у Win 98: играть, обновиться, узнать новое. Но это страница сайта Star Rail 98, а не окно Win 98. Игрок скачал игру с сайта и видит у себя на ПК ту же страницу.

- Картинки статичные: кадры `hsr98-1.jpg` и `hsr98-2.jpg`. Скрипты игры для рисования картинок, как на сайте, лаунчер не грузит: 170 скриптов занимали бы секунду при каждом запуске.

- «Что нового» каждой сборки берётся из `releases/sr98/<версия>.md`, как у Win 98. Настоящая дата выпуска стоит только в билете: «Дата выпуска: 02.11.2026».

## Кнопка «Обновления» в APK

### Пункт главного меню

Пункт есть только в издании APK: `Hsr98Standalone === 'apk'` и есть мост `Sr98Android.checkUpdate`. Он стоит последним, после «Настройки».

| --- | --- |
| не проверялось | «Версия 1.6.3 · проверить обновления» |
| последняя | «Версия 1.6.3 · последняя» |

### Устройство

- Запросы делает Java, а не `fetch` страницы: pennygachi.men отдаёт статичные файлы без CORS, а страница APK живёт на другом адресе.
- `Sr98Android.checkUpdate(channel)`: GET `update/sr98/<channel>.json`, ответ в `hsrui.updateInfo(json)`.
- `Sr98Android.downloadUpdate()`: APK в `getCacheDir()/update/`, прогресс в `hsrui.updateProgress(done, total)` раз в 200 мс, проверка sha256 из указателя, затем `hsrui.updateReady()`.
- `Sr98Android.installUpdate()`: на Android 8+ `canRequestPackageInstalls()`. Если нельзя, `hsrui.updateNeedsPermission()` и `ACTION_MANAGE_UNKNOWN_APP_SOURCES`, при возврате в `onResume` проверка ещё раз. Затем `PackageInstaller`: сессия, запись файла, `commit` с `PendingIntent` (на Android 12+ нужен `FLAG_MUTABLE`), на `STATUS_PENDING_USER_ACTION` открыть системное окно, итог в `hsrui.updateResult(status)`.
- `Sr98Android.versionCode()` для сравнения с указателем.
- `AndroidManifest.xml`: `android.permission.REQUEST_INSTALL_PACKAGES`.
- Скачанный APK удаляется при следующем запуске.
- Экран и пункт меню: `js/apps/hsr98/hsr-ui-update.js` (подключён в `hsr98.html`, работает только при мосте `Sr98Android`). Значок `update` в `G.menuIcon`. Ключи `sr98.update.*` (время проверки, последняя запущенная версия, канал) идут в `backup-catalog.js` рядом с `sr98.bugs.sent`.
- Сайт sr98: «Android версия» берёт ссылку и размер из `update/sr98/stable.json` (тот же домен, CORS не нужен), данные в `index.html` остаются запасными. Новый APK на сайте появляется сразу после выпуска, без заливки сайта.

## Выпуск: `tools/release.cjs`

`npm run release -- <команда>`

| Команда | Что делает |
| --- | --- |
| `keygen` | создаёт ключ подписи в `%USERPROFILE%\.win98-release.key` и печатает открытый ключ для `electron/updater.js` |
| `win98 [--channel test] [--full]` | сборка exe с версией, манифест, блобы, тексты, исправленные отчёты, подпись, проверка запуска, заливка. С `--full` ещё собирает и заливает `Win98.zip` |
| `sr98 [--channel test]` | standalone, `StarRail98.exe` и архив, APK, `sr98/play`, манифест, тексты, заливка (этапы 6 и 7) |
| `news` | только новости, без сборки |
| `promote <продукт> <версия>` | копирует указатель test в stable |
| `status` | что выложено: версии, каналы, место на сервере |
| `verify <продукт> [--channel test]` | проверка снаружи через Cloudflare: подписи, 20 случайных блобов, Range |
| `gc [--keep 5]` | удаляет блобы и архивы, на которые не ссылаются последние 5 версий каждого продукта |

Порядок `win98`:

1. Рабочая копия без незакоммиченных изменений, иначе отказ. `--dirty` разрешён только для канала test.
2. Версия = последняя на сервере + 1.
3. `npm run build:exe` с версией, в сборке появляется `release.json` с манифестом.
4. Сжатие и хеши в `dist/release/win98/blobs/`.
5. Тексты: `next.md` становится `1.15.md`, из текстов собираются `notes.json` и `news.json`, к ним добавляются исправленные отчёты.
6. Подпись всех JSON.
7. Проверка запуска собранного exe с временным профилем через CDP: лаунчер открылся, «Запустить» доводит до рабочего стола системы, исключений 0.
8. Заливка. Список блобов на сервере (`ssh mini-pc find ...`), новые блобы одним tar через `scp` в `~/release-incoming/` (вне папки сайта), `sha256sum -c` на сервере, распаковка GNU tar и `mv` в `update/blobs/`, затем манифест, тексты и новости. Указатель заливается последним: запись во временный файл и `mv`. Раздел на мини-ПК один (ext4 `/`), поэтому `mv` атомарен. Игрок никогда не видит указатель на недолитые файлы и недописанный файл.
9. `verify` снаружи.
10. Коммит `releases/` и статусов отчётов делает автор или Claude по просьбе.

Первая заливка Win 98 = 1,9 ГБ блобов. Если по Tailscale это долго, `release.cjs` может собрать блобы на самом мини-ПК из уже залитого `Win98.zip` той же сборки: Node там есть со времени приёмника отчётов.

## Безопасность и приватность

- Лаунчеры и APK только скачивают файлы. Об игроке ничего не отправляется.
- Подпись Ed25519 на всех JSON выпуска, sha256 на каждом блобе, HTTPS.
- Функции обновления доступны только окну лаунчера.
- Закрытый ключ подписи и `hsr98.keystore` хранятся вне git, копии у автора.
- Заливка только по ssh через Tailscale. Публичного адреса для записи на сервер нет.
- Тексты экранируются, ссылки ведут только на pennygachi.men.

## Риски

| Риск | Что делаем |
| --- | --- |
| Сломанный выпуск у всех игроков | проверка запуска перед заливкой, канал test, откат в лаунчере |
| Упал VPN Sota или туннель | лаунчер показывает «Нет связи», игра работает |
| Cloudflare ограничит раздачу больших файлов (условия CDN бесплатного тарифа) | Win98.zip уже раздаётся так же; обновления по файлам уменьшают трафик; блобы можно перенести, поменяв поле `blobs` в указателе |
| Потерян ключ подписи или keystore | копии у автора; без них игроки ставят полный архив, а APK только через удаление (сохранения уцелеют только после «Переноса») |
| Антивирус держит файл при замене | повтор переименования, журнал |
| Игрок распаковал в `Program Files` или в папку OneDrive | понятное сообщение; в OneDrive проверка файлов может скачивать их из облака |
| У Claude нет телефона для проверки APK | этап APK закрывается только после проверки на телефоне автора |

### Этап 10. Обновление Electron без полного архива (по желанию)

Работающий exe нельзя перезаписать, но можно переименовать. Лаунчер скачивает новые файлы Electron, переименовывает старые в `*.old`, ставит новые и перезапускается. При следующем запуске `*.old` удаляются. Этап нужен, только если Electron будет меняться чаще пары раз в год (В5).

## Решения автора (28.10.2026)

1. Версия Win 98 `1.N`, первая сборка с лаунчером 1.0, каждый выпуск +1, в скобках дата сборки: `1.0 (28102026)`.
2. Лаунчер Win 98 показывается при каждом запуске, флажок «Сразу запускать, если обновлений нет» по умолчанию выключен.
3. Star Rail 98 для ПК делаем отдельной программой `StarRail98.exe`.
4. Номер сборки SR98 вида `1.6.3`: два числа из `Hsr98.VERSION`, третье растёт с каждым выпуском.
5. Сменился Electron: игрок качает полный архив. Самообновление Electron только этапом 10.
6. APK: тихая проверка раз в сутки при открытии главного меню и метка NEW.
7. APK сам скачивает файл и открывает установщик Android.
8. Канал test для проверки выпуска до игроков есть.
9. «Что нового» пишет Claude по коммитам, автор правит перед выпуском. Тексты только на русском.
10. Новости SR98 = новости сайта sr98, вынесенные в `news.js`.
11. `Win98.zip` на сайте пересобирается только при смене Electron или по `--full`. Новые игроки докачивают обновление лаунчером.

## Что не входит в план

- Браузерная версия SR98: она обновляется сама при перезагрузке страницы (скрипты с `?v=`).
- Вымышленный сайт «Обновление Win» внутри системы.
- Разностные патчи внутри файлов: изменился файл, значит качается файл целиком.
- Статистика загрузок и любая телеметрия.
- Обязательные обновления и запрет играть в старую версию.
- Ссылки из новостей внутрь системы или игры («открыть в Steam»).
- Новости письмами в Outlook Express или репликой Скрепыша.
- Установщик с ярлыками в меню «Пуск» Win 10/11: остаётся архив.
- Подпись exe сертификатом: SmartScreen предупреждает, как и сейчас.
